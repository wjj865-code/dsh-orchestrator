## 3. 关键实现决定（评审要看的三点）

### 3.1 React / `req` / `h`

- factory 参数名从 `require` 改成 `req`（设计文档要求，绕开 rollup/esbuild 的 commonjs 启发式）；
- `React`/`h` 只在 `client/src/client.js` 里由 `req('react')` 产生，其余模块通过工厂参数拿；
- `client/src/**` 里**没有** `from 'react'` / `require('react')`（构建契约测试源码扫描守着）。

### 3.2 样式表：`styles.css` + `?inline`

平台 `/plugins/<id>/*` 的 assets 路由只白名单图片，`.css` 一律 404 → 样式只能进 JS。所以：
`styles.css`（真 CSS 文件，唯一真相）→ `import STYLE_TEXT from './styles.css?inline'`（构建期变成字符串）
→ `ensureStyles()` 注入 `<style id="dsh-orchestrator-styles">`。CSS 内容逐字与旧 `STYLE_TEXT` 一致（含注释）。

> 副作用（已核对）：`dist/client.js.map` 的 `sources` 只列 9 个 JS 模块，**不含 `styles.css`**——Vite 把 CSS
> 内联成字符串常量，不建 CSS→JS 的 mapping。改 CSS 仍会改产物字节（可复现性检查照样有效），只是单步调试
> 跳到源码时需要知道这一点。

### 3.3 为什么「行级比对」能证明功能没丢

搬运用一次性脚本按行区间切片 + 统一缩进（不重排、不改表达式），搬完做两项机械核对（§5.4）：
1. **旧 JS 行集合 ⊆ 新源码行集合**（去缩进后逐行比对）→ 缺的 47 行全部是 `const X =` 加了 `export ` 前缀、
   `const React = require('react')` 改成 `req('react')`、以及两个文件头注释块（`STYLE_TEXT` 注释 / `ensureStyles` 注释）；
2. **旧 CSS（77–782）逐字出现在 `styles.css`**。

另外做了名字级核对：旧 `client.js` 里 57 个顶层声明 **57/57** 都能在新源码里找到（见 §5.4 表）。
