## 3. 语义冲突（3 处）与决策

### ① keepAlive：保持删除，文案意图移植

- 远端 `27222f2` 只改了 `src/keepalive.js` 的一句提示词（「会停在『已交付待确认』，确认或超时后才收成完成」）。
- 决策：**不复活** `src/keepalive.js`（P2-2 已把续跑交还宿主 `dsh-goal-round-driver`），把该口径落到仍在用的文案单源：
  - `src/copy.js`：`deliveredReceiptNote` / `finishHint` / `DELIVERY_LINES`（确认或超时才收成完成）；
  - `src/brief.js`：`CONFIRM_HINT`「交付后协调者不会为能不能关闭来问你，任务留待确认、等超时自动完成」；注释同步；
  - `src/handoff.js`：`handoffStatusLines` 的「未确认（等你或用户确认，或超时自动完成）」。
- 校验：`git grep keepalive -- src` 只剩配置弃用警告与台账旧列 `keep_alive_rounds`（停写、保留兼容）；`test/goal.test.js` 的静态扫描（`src/` 不得出现 `turn-stopping` / `createKeepAlive`）通过。

### ② 配置卡片：按 `loadConfig()` 实际 28 键投影

- 远端 0.22.0 的卡片投影 35 字段（含 P2-2 已删的 7 键）。决策：卡片跟随**运行时真实键集合**。
- 改动：`src/config-fields.js` 删除 `keepAlive` / `keepAliveMode` / `keepAliveMaxRounds` / `keepAlivePrompt` / `mergeWindowMs` / `stallRounds` / `preferencesMaxItems` 与空的 `keepalive` 分组 → 35 → **28**；
  `src/config-schema.js`（投影）与 `client/src/config-form.js`（表单）自动跟随，无需另改。
- 测试：`test/config-fields.test.js` 新增「已删 7 键不得回到表单」「字段表 = 28 键 + 无 keepalive 分组」两条断言，并把 `Config` 垃圾值/解包用例里用旧键做样本的地方改成真实键（`autoResumeQueue` / `maxQueue`）；`test/client-config-form.test.js` 的 `buildOps` 样本同步改成真实键。
- 校验：`loadConfig({})` 28 键 == `FIELD_KEYS` 28 键（互无多缺）；`dist/client.js` 内不含任何已删键字面量，且含 `.orch-cfg*` 表单类。

### ③ dist：用 `pnpm build` 重建，不手合

- `dist/client.js` / `dist/client.js.map` 在 P2-1、P2-5 两处冲突；决策：rebase 过程中取 P2 侧产物，收尾统一 `pnpm build`（esbuild minify + sourcemap 保留）重建。
- 实测：`dist/client.js` = **93,749 B（91.6 KiB）**，预算 95 KiB（97,280 B），余 3.4 KiB；`dist/client.js.map` = 245,048 B。
