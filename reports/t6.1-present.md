## 1. 改了什么（`src/notify.js`）

### 1.1 产物候选判据（与平台 `present` 完全对齐）

| 分类（`classifyPath`） | 依据 | 处理 |
|---|---|---|
| `file` | `lstatSync(path).isFile()` | **进候选**，按原顺序、按路径去重 |
| `directory` | `lstat.isDirectory()` | 跳过，计入「目录 N」 |
| `symlink` | `lstat.isSymbolicLink()`（Windows junction 同样报 symlink） | 跳过，计入「符号链接 N」 |
| `missing` | `lstat` 抛 `ENOENT` | 跳过，计入「不存在 N」 |
| `relative` | `!isAbsolute(path)` | 跳过，计入「非绝对路径 N」 |
| `other` | 其它 stat 错误 / 空路径 / 非字符串 | 跳过，计入「不是普通文件 N」 |

> 依据：`dsh-tool-present/src/index.ts:88-93` 先 `ctx.fs.lstat` 判 `entry.type !== 'file'`（目录、符号链接都拒），再 `stat` 判存在（`FS_NOT_FOUND`）。也就是说**目录或链接混进候选 = 整次 present 报错**，不是「少交付一个」，所以必须在插件侧先过滤（T0.1 §4.1「T6.1 过滤目录 → 要扩到符号链接 + 不存在」）。

### 1.3 上限与折叠口径

- `PRESENT_MAX_FILES = 4`（产品上限；平台硬上限 8，见 D6）。
- 折叠数 = `候选总数 - 4` + `item.artifactsTruncated`（后者是台账层截断、根本没进 `item.artifacts` 的条数），两者合成一条「另有 N 条产物未列出」。
- 合并窗口内的多条任务：每条只列自己的产物，**交付指令在整条消息末尾写一次**（`batchHint`），避免 N 条任务刷 N 遍指令；单条消息仍走 `artifactBlock(item)`。
- 去重：同一绝对路径被显式回报 + `workspaceChanges` 自动收集各报一次时只列一条。

## 2. T0.1 相关差异表条目是怎么纳入的

| T0.1 条目 | 探针结论 | 本单落点 |
|---|---|---|
| **D6** | `present.maxFiles` 默认 **8**；「最多 4 个」只是 schema 描述里的建议 | 4 保留为**插件产品上限**（`PRESENT_MAX_FILES`），注释与测试都写清「平台硬上限 8」；测试断言的是插件输出的候选数，不冒充平台拒绝第 5 个 |

| **D7 补** | 文件必须已存在，否则 `FS_NOT_FOUND` | 不存在直接不进候选，并在「不能交付（不存在 N）」里计数 |

| §3.3 | 卡片读的是成功后追加的 `deliverables/presented` 事件，不是工具返回文本 | 单测只断言插件产出文案；「卡片真的出现」留给 T6.4 真机复核（本单不伪造渲染结论） |
| §4.1 | 绝对路径可指向工作区外（target / 未来 worktree 检出目录同理） | 只要求 `isAbsolute`，不限定在 target 目录内 |
