# 公众号写作

把用户的想法写成**可排版、可建草稿**的 Markdown。你只负责文字；排版交给文颜（见 `wechat-mp-format`）。
**不要自己拼 HTML、不要自研样式**——公众号编辑器只认文颜那种全内联样式。

## 产出位置

在工作目录下建 `out/`，文章写 `out/article.md`（文件名固定，后续命令都用它）：

```
out/
  article.md      # 正文 + frontmatter（title 必填）
  assets/         # 图片（可选；相对路径从 article.md 所在目录算）
```

## frontmatter（必读）

```markdown
---
title: 标题（必填，公众号文章标题）
author: 作者名（可选）
digest: 摘要（可选，公众号「摘要」栏；不填则微信取正文前 54 字）
cover: assets/cover.jpg（可选；建草稿时上传为封面）
source_url: https://…（可选，原文链接）
---
```

- `title` 必填；没有它文颜会直接报错。
- 图片用相对路径（`assets/x.png`）时，命令的 `-f` 必须是本地文件路径。
- 不要在 frontmatter 里写凭据、AppID/Secret 或任何 token。

## 写作要求（公众号场景）

1. **开头 3 行决定去留**：先给结论/场景，再展开；不要「随着……的发展」这类空转。
2. **一段一个意思**：移动端一行约 18–22 字，长段落在手机上是灾难；每段 ≤ 4 行。
3. **小标题用 `##` / `###`**：文颜会把它们渲染成带样式的标题块；不要用加粗假装标题。
4. **标题**：具体、有信息量、不标题党；给 2–3 个备选让用户选（10–24 字为主）。
5. **摘要 digest**：一句话说清「读完能得到什么」，≤ 120 字。
6. 代码用围栏代码块并标语言（文颜做高亮）；表格仅在必要处用，列数 ≤ 4。
7. 结尾给一个可执行动作或一句可引用的判断，不要「欢迎点赞关注」这类填充。

## 自检（交付前）

- [ ] `out/article.md` 首行是 `---`，frontmatter 有 `title`
- [ ] 没有绝对路径的图片引用（除有意使用网络图片 URL）
- [ ] 标题/摘要都是最终版，不是占位符
- [ ] 正文里没有残留的 TODO、示例假数据、真实凭据

写完告诉用户：下一步可以用 `wechat-mp-format` 看排版，或直接 `wechat-mp-draft` 建草稿（需要先装 CLI + 设置环境变量）。
