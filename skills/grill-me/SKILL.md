# grill-me：动手前把需求拷问清楚

目标：在写第一行代码、派第一个子任务之前，把「到底要什么、不要什么、怎么算做完、哪条路不能走」逼问出来。
拷问的对象是**需求**，不是用户：问题要尖锐，态度要客气。

## 一句话规矩

- **一次只问一个决定性问题**：一轮只推进一个「前沿」，问完等回答，不连珠炮。
- **每问必须带我的推荐**：`2–4 个选项 + 我推荐哪个 + 一句为什么`。只抛问题不给建议＝把决策成本推回给用户。
- **事实我自己查**：文件内容、历史决策、仓库事实、当前配置——能查到的绝不问用户。
- **决策归用户**：我只负责把选项、代价、推荐摆清楚；取舍由用户拍板，不替用户选。
- **grill ≠ 批准**（见文末）：澄清完只是「需求清楚了」，不等于任何授权。

## 怎么问

1. **先只读调研**：用 `read`（单个文件）/ `context({ mode: 'history' | 'project' })` / `task_list` 把能自己确认的事实查清；需要跨文件检索或枚举目录时派一条只读任务（协调者没有 glob/grep）。查不到再问。
2. **列决策点**：把模糊处写成 3–6 条候选决策点，只留「会影响下一步动作」的——目标、范围、验收、代价取舍、不可逆项或权限。
3. **按依赖排序**：上一问的答案会改变下一问的选项时，顺序就定了；先问「选哪条路」，再问「这条路里的参数」。
4. **结构化提问**：协调者用 `ask_user_question`（question + 2–4 个 options），不要把一串纯文字问句丢给用户。
5. **一问一次**：同一个点只问一次；用户答「随便 / 你看着办」时按推荐继续，并在回复里写明「我按 X 做，随时可改」。

## 前沿提问（frontier）

「前沿」＝当前最能改变方案的那个未知。每轮只推一个：

- **优先**：不可逆的、代价最大的、会卡住后面多个决策的、与用户真实意图偏差最大的。
- **不问**：能自己查的事实；已有默认值且可回退的细节（命名、文案、顺序）；用户刚说过且没改口的事。
- **换前沿**：用户答完，重新算一遍「现在最大的未知是什么」，而不是照着事先的提纲一路问完。

## 上限：2 轮 / 8 问

- 一轮最多 **4 问**，总共最多 **2 轮 8 问**。到上限不再问，直接给决策记录。
- 第二轮只在「第一轮的答案引出了新的分叉」时才用；没新分叉就一轮结束。
- 8 问还没收敛，说明需求本身太大：改成「先做最小可验证切片」，把剩下的大问题写成下一轮的输入，而不是继续追问。

## 决策记录（三栏）

拷问结束必须产出一张表，直接进回复/计划文档：

| 决策点 | 你定的 | 影响 / 后续动作 |
|---|---|---|
| 例如：报表空窗口要给说明还是给空表 | 给说明（用户拍板） | 改渲染层 + 加一条验收 |
| 例如：历史数据要不要回刷 | 未定 | 按推荐「不回刷」执行，留 TODO |

- 只记**用户拍板或明确接受**的结论；我推荐但用户没表态的，第二栏写「未定」，第三栏写「按推荐 X 执行」。
- 同一张表就是 `task_create` 的输入：结论写进 `goal` / `constraints` / `user_verbatim`，别让子会话再猜一遍。

## 与交互三闸门衔接

- **T0 / T1 不 grill**：能直接答就答；单点可回退的改动直接做，只在回复里写一句「我的理解：…」。
- **T2**：先 Grill（通常 1–2 问就够），再**一次**把「我的理解 + 决策记录」给用户，用 `ask_user_question` 确认；确认后才 `task_create`。
- **T3**：Grill 的结论写进计划任务的 `goal` / `constraints` / `user_verbatim`，然后走 `task_create({ planFirst: true })` 的四步——计划批准仍然**必须用户拍板**，grill 不替代它。
- **执行期不 grill**：开工后只处理四类堵塞项；需求追加按 R0–R2 先评估、再确认。

## grill ≠ 批准

- Grill 只澄清需求，不构成任何批准：不批准计划、不批准不可逆操作、不批准权限变更或远端写。
- 用户回答了一个 grill 问题 ≠ 批准执行；只有明确说「批准 / 按这个做 / 可以执行」才算批准，且计划批准必须由用户在 `ask_user_question` 里点选。
- 反过来：用户说「别问了，就按你的推荐做」时立刻停，输出决策记录按推荐继续——但**不可逆项与计划批准仍要单独拍板**。

## 停止条件

- 用户说「别问了 / 够了 / 就按你说的做」→ 立刻停，给决策记录，按推荐继续。
- 已经问到 8 问、或 3 问都没有新信息 → 停，给决策记录 + 还没定的点。
- 发现需求本身需要重新定义（目标变了、范围翻倍）→ 停，先把这个发现讲清楚，别继续追问细节。
