## 并行策略（互不依赖、无需复用上下文时优先 worktree 隔离并行）

- 判断标准（三条同时满足才并行）：① **互不依赖**——B 的输入不是 A 的产物、谁先谁后都行（不建 dependsOn）；② **不需要复用同一子会话上下文**——不是追问、续写，也不是同一份计划的后续轮次；③ **同一写域会撞车**——target 相同/互相包含，或 writeScopes 重叠（不撞车就直接并行，不用建检出）。
- 优先并行：三条都满足时，新任务**直接传 `worktree: true`** 在独立检出里并行跑；不要为了省事把两个互不依赖的任务串成 dependsOn 链，也不要在同写域被拒时默认「先关旧任务、再重派」——串行是**有依赖**时的解法，不是默认姿势。
- 只有这两种情况才串行：① **有依赖**（B 要用 A 的产物 → 建 dependsOn，见 orch-task-chain 技能）；② **要复用同一子会话上下文**（续写/追问同一份活 → `task_message` 追问原会话；复用同一检出 → `worktreeMode: "continue"` 并串行）。
- 代价（并行前跟用户说清楚）：① 产物在各自分支的检出里，**合并由用户决定**——并行越多合并面越大，别把同一批文件拆成两条并行；② 每个检出都是空目录，子会话要先装依赖（`pnpm install` / `npm install` / `uv sync`，只装不升），第一个任务会慢一点；③ 并发 `git commit` 会争 `.git` 锁。
- 例外（不必隔离）：**只读任务**（`readOnly: true`）与**计划阶段**（`planFirst: true` 批准前）不改文件，同目录并行也不冲突，直接派；**同一 worktree 检出永远只能一个任务在写**——`worktreeMode:"continue"` 复用或同一条链上的任务必须 dependsOn 串行。
- 与三段口径的关系（一致，不互相推翻）：① 「同写域并发防护」默认**拒绝**同目录并行，被拒时先考虑 worktree:true 并行，只有「这个目录确实只该有一个任务在写」才关旧任务重派；② 「任务链」只用于有依赖的链，不是给无依赖任务排队用的；③ 「worktree 隔离」讲怎么建检出，本段讲什么时候该并行、什么时候必须串行；④ 计划批准、两段式交付、同写域判定、任务链失败传播这些硬规则一条没变。
